# PRD 48 — v0.2.0 Risk, Testing & Decision Register

**BLUF:** The v0.2.0 version of the repo's risk register (PRD 08), engineering-rigor plan (PRD 38), threat model,
and ADR set — scoped to the new features. A release gate, not prose: every risk has a mitigation, every new trust
surface has a test, every architectural decision has an ADR number reserved.

**Status:** shipped in v0.2.0 (2026-10-08) — originally proposed v0.2.0 (2026-10-05) · **Parent:** agentsec-ecosystem #209 · **Milestone:** M25–M28 ·
**Depends on:** PRD 08, PRD 38, `design/threat-model.md`, `adr/README.md` · **Extends:** PRD 08, PRD 38

> Cross-cutting rules (PRD 19–30): fail closed and never silent (PRD 17); redaction before storage (DD-06);
> the trust boundary stays deterministic — no LLM in redaction, validation, or chain verification; monitor-only,
> every hook exits 0 (R2); local-first, no egress without explicit opt-in (R6); no new runtime dependency
> without a recorded decision (NFR-5); conformance and quality gates apply (NFR-11).

## 2. Testing & rigor extensions (PRD 38 / M14 Q-series applied)

- **Fuzz** (`test_fuzz_parsers.py`): AAT records, Cursor hook JSON, Codex rollout lines, Gemini OTel telemetry,
  gateway OTLP, A2A JSON-RPC; regression-seed the Codex #36937 backtick-execution payload — parsers contain, never
  execute.
- **Property-based**: sampler determinism (same session → same decisions cross-replay); AAT round-trip
  lossless-or-explicit; identity fields never contain secret material; Postgres rebuild bit-identical.
- **Mutation gate**: extend the trust-path mutant set to the AAT mapping, sampler logic, stream reconciliation.
- **Perf gate**: p99 hook→operator-view ≤ 1 s (STR); ingest throughput floor for 100 MB OTLP/rollout; no regression
  on the existing 2 ms/step floors.
- **Soak**: 24 h with streaming consumers + rolling Postgres rebuild + drift job active.
- **Conformance packs**: every new adapter/reader/ingest (Cursor, Codex, Gemini, AAT, A2A, ACS) registers in O1.
- **Executable docs**: every recipe (EXA-1) and compliance-report row (CMP-1) runs in CI (Q10).
- **Claims ledger**: entries for every published number (detector precision/recall, latency, compatibility rows).
- **Field test** (FLD-1): AAT third-party verification; Cursor corpus fidelity audit; hostile-session replay drill
  (R5); detector reproduction on a second corpus.

## 3. Threat-model additions (`design/threat-model.md` + recorder attack matrix)

1. **Foreign-data weaponization** (R5): ingest inputs are attacker-controlled; executable-shaped content must never
   reach a shell/eval/pipe (the Codex #36937 lesson). Controls: no shell on ingest; redaction-before-store;
   `replay` render-only; bundles label content untrusted.
2. **Streaming side-channel**: a live view is a lower-latency read path — views derive from the same
   append-then-verify records; back-fill is authoritative.
3. **Proxy surface growth** (MCP full-surface + A2A): more attacher-reachable parsing; containment (fuzz, bounded
   buffers, quarantine); **A2A card signature verification is a trust decision** — record outcome, never silently trust.
4. **Compliance-API pull** (CCA): egress-adjacent → explicit opt-in, pulls recorded as `store-access`, credentials
   session-scoped.
5. **Identity-field abuse** (IDN): SPIFFE/emails create a surveillance surface → hashed by default; operator consent
   for plaintext identity.
