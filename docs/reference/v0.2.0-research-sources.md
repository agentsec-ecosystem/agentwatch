## 11. Permission modes, approval behavior & auto mode (→ PRD 49, 54)

- **Claude Code auto mode** — model-classifier approvals: "How we built Claude Code auto mode: a safer way to skip
  permissions" (anthropic.com/engineering/claude-code-auto-mode, 2026-03-25). Users approved **~93%** of permission
  prompts; auto mode built to reduce approval fatigue. Classification: vendor engineering post.
- **Auto mode becomes default** — "Auto mode is now the default in Claude Code for Pro, Max, and Team plans"
  (claude.com/blog/auto-mode-default-in-claude-code, 2026-08-07): default from **2026-08-14**; users approve **97%** of
  prompts; plan rejection 39% vs permission rejection 3%; **62%** have used `bypassPermissions` or "don't ask again" on
  Bash; **25%** of interactive sessions start in bypass; in a 1,053-tester study testers caught a swapped dangerous
  command **13.6%** (143/1,053) while auto mode blocked **89%**. Classification: vendor blog.
- **Containment** — "How we contain Claude across products" (anthropic.com/engineering/how-we-contain-claude,
  2026-05-25): auto mode catches ~83% of overeager behaviors; classifier misses ~17%; sandbox cut prompts **84%**;
  fallback to manual after 3 consecutive / 20 total blocks; OS sandbox open-sourced. Classification: vendor engineering post.
- **Permission modes** — code.claude.com/docs/en/permission-modes: `default | acceptEdits | plan | auto | dontAsk |
  bypassPermissions`; allow-rules broad enough to grant arbitrary execution (e.g. `python:*`) still bypass the classifier;
  critical-path `rm`/`rmdir` never auto-approved. Classification: vendor docs.
- Maps to: APV-1 (authorization taxonomy), APV-2 (mode per call), APV-3 (`oversight` report).
- **verify:** the exact hook/event field that carries the classifier decision and mode at the moment of a call.
