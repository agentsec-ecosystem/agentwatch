# Runbook — Windows install & verify

Goal: record on Windows (enterprise endpoints) with the daemon supervised at logon.

agentwatch runs on Windows as a normal user process (no kernel driver). Hooks are
fire-and-forget (`agentwatch-hook pre|post`) and reach the daemon over a local
endpoint; the daemon is kept alive by a **Task Scheduler** task generated by
`agentwatch init --service` (Task Scheduler XML, least privilege, restart on
failure).

```powershell
# 1. Install the SDK + hooks
python -m pip install agentwatch
agentwatch init --service           # writes %APPDATA%\agentwatch\agentwatch-task.xml

# 2. Register the task (operator-run; schtasks consumes the generated XML)
schtasks /Create /TN "agentwatch" /XML "$env:APPDATA\agentwatch\agentwatch-task.xml"

# 3. Confirm recording
agentwatch status
agentwatch sessions
```

## Verify

- [ ] `agentwatch status` shows recording active.
- [ ] A tool call appears in `agentwatch sessions` within the ingestion window.
- [ ] The scheduled task runs at logon (`schtasks /Query /TN agentwatch`).
- [ ] Redaction self-test passes before any export.

## Notes / limitations

- The **Windows CI leg** (`.github/workflows/windows.yml`) exercises the
  platform-independent SDK subset (service-unit generation, packaging, import) on
  `windows-latest`.
- The **named-pipe transport** and an end-to-end CUJ-1 timing run on Windows are
  tracked on WIN-1 (#350); this runbook is honest about that until they land.
